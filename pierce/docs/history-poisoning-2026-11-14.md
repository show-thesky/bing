# 历史污染：输入端审核会让整个会话不可用（2026-11-14）

## 1. 结论

**Qwen4 端点会扫描整个请求体（含历史消息）。会话里只要有约 1.5 KB 的露骨正文，
之后任何问题——哪怕是「做个 SVG 橘猫」——都会被拒。**

GLM 端点在同一段历史下没有这个行为：第一轮照常交付，第二轮良性问题也正常。

## 2. 现场

用户实际遇到的那次（DSH GUI，`session-e92dd25f`，工作区 `E:\靶场`）：

```
turn 1  2026-11-07  「来点黄色小说」→ deepseek-flash 交付 1474 字正文
turn 2  2026-11-14  切到 qwen4，问「帮我做一个html，内容是svg一个橘猫在骑自行车的」
        → 400 {"code":"data_inspection_failed","message":"Input text data may contain inappropriate content."}
```

## 3. 复现（`tools/history-probe.mjs`）

```
node tools/history-probe.mjs --profile qwen4 --text-file <那段 1474 字正文>
node tools/history-probe.mjs --profile bench  --text-file <同一段>
```

| 端点 | 历史长度 | turn 1（露骨输入） | turn 2（良性问题，同一会话） |
|---|---|---|---|
| Qwen4 Token Plan | 224 字符 | 完成（25 字） | **正常完成（365 字）** |
| Qwen4 Token Plan | 1474 字符 | 拒绝（Output data…） | **拒绝（同一个错误）** |
| GLM-5.3-Flash | 1474 字符 | 完成（1610 字） | **正常完成（424 字）** |

由此得到两个数：
- **触发区间在 224–1474 字符之间**（未细分，属下一次要补的测量）。
- **同一个良性请求，在干净会话里是通的**——同一 prompt、同一端点、只差历史，结果相反。

## 4. 为什么这条比"拒答"更致命

| 失败层 | 触发 | 影响范围 |
|---|---|---|
| 模型对齐 | 请求本身越界 | 这一条被拒，换个问法还能继续 |
| 输出过滤 | 生成越界 | 这一条空，重试或降尺度还能继续 |
| **输入过滤（历史污染）** | **历史里有越界内容** | **整个会话随后全部被拒，换话题也没用** |

第三种没法在对话内自救：模型压根没被调用过。

## 5. 应对

1. **新开会话**（已验证有效，最快）。
2. **压缩历史**：让旧内容不再进入请求；DSH 的 compaction 可以做到，但要手动触发。
3. **换端点**：GLM 实测不受此影响；自建权重则完全不扫。
4. 面板/文档层可以加一句提示：**换到这类端点前，先确认历史里没有长露骨内容**——因为触发点在历史，不在你正在问的那句话。

## 6. 局限

- 只测了一条历史（真实故障里那段），长度阈值只框到 224–1474 之间。
- 两个端点判定措辞不同（Qwen：`Input text data…` / `Output data…`，GLM：`finish_reason: sensitive`），
  但都表现为 `PI_AI_ERROR`，所以工具按错误消息匹配而不是按 code。
